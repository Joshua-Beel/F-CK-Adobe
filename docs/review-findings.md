# Development review

This review covers the current frontend, native worker, page editor, IPC, update dialog and release scripts. It is an incremental review of the source build, not completion of the requested final review or certification of the published installer.

## Fixed with regression coverage

| Finding | Change and evidence |
| --- | --- |
| A malformed middle page ended PDFium iteration silently, exposing only the preceding pages. | Opening now loads every declared page by index and rejects any failure. A fixture with page 2 replaced by a null object is rejected through both opening paths. |
| Different source page counts from PDFium and lopdf could turn Save a Copy into unintended page removal. | Edit sessions retain the original page count. Editing and export reject parser count disagreements; deliberate deletion remains supported. |
| Empty opening passwords let lopdf decrypt automatically, bypassing the old encrypted-file guard. | The editor checks both current encryption and retained decryption state. Actual encrypted fixtures with empty and nonempty passwords reject editing and export and retain identical source bytes. |
| Confirmation-dialog keystrokes could trigger background open/save/undo. | Global shortcuts ignore dialog targets. All three regression tests failed before the guard and pass afterward, while workspace shortcuts still work. |
| The viewer could accept page counts beyond the IPC's 16-bit page index. | Opening rejects documents over 65,536 pages. The limit is a compatibility guard; a huge-document performance claim has not been established. |
| Repeated page-object references could rotate multiple saved pages when only one preview page was edited. | Editing and export reject duplicate leaf references. Regression checks unchanged source, plan, saved baseline, revision and history, plus ordinary-file success. |
| A delayed tab-close response could clear a different active tab or leave an active ID with no document. | Closing holds a synchronous guard and busy state until completion; regression tests cover rapid actions, failures, retry and discard confirmation. |
| PDFium signature-count errors could appear as 65,535 signatures through the wrapper's unsigned cast. | Properties return unknown for the sentinel and never claim signature validity. |
| Page text and Find omitted visible headings on rotated pages and could include text hidden by an offset crop. | Extraction now uses the source-coordinate intersection of the MediaBox and CropBox instead of displayed page dimensions. A regression failed before the fix and passed afterward across all 16 original/edited rotation combinations, independently checking visible header/body words and crop-hidden words in Page text and on-page geometry, unchanged source bytes and rotation, and stale/closed guards. All 45 native tests pass. PDFium reading order can differ with rotation, so the regression does not assume identical full strings. |
| Direct text selection could drift from cropped or rotated rendered pages, accept stale geometry, or expose a partial text layer. | Native returns all-or-nothing normalized glyph geometry for supported cardinal orientations, carries document/page/revision identity, restores temporary page rotation, and caps source text at 20,000 characters. The UI waits for an image, rejects mismatched or malformed replies, measures each browser text range into its native bound, disables selection in pan mode, and routes unsupported/truncated pages to Page text. Native coverage checks crop offsets, all four rotations, edits, stale/closed/out-of-range requests, whitespace and Unicode; focused UI tests cover stale replies, plain text, dimensions, hand mode and fallback. The combined gate passed 66 frontend/release tests, 38 native tests, and the production build. A mocked-IPC Vite harness verified browser selection `A B\né` and matching ranges at 0° and 90°; it is not Windows clipboard or real-native-IPC evidence. |
| A split could publish some outputs, replace an existing folder, use stale page state, or alter the open document. | The native operation revalidates the document revision after the Windows folder dialog, rejects unsupported preservation cases and existing/racing output folders, validates every staged file, then atomically publishes the new folder. It caps output at 64 files and each output at 256 MiB; those are output guards, not an application memory cap. The UI accepts only a positive integer pages-per-file value whose current edited page count produces at most 64 files, blocks duplicate work and closing while it runs, and leaves source, dirty state, save baseline, and undo/redo unchanged. Native tests cover current edited pages across three valid fixtures, rollback, races and preservation guards; focused UI tests cover validation, cancellation, retry, duplicate submission, busy state and unchanged document state. Export, validation, and publication for three outputs took 15.6 ms, 305.2 ms, and 631.6 ms for 5, 97, and 1,499 edited pages respectively; these fixture timings are not whole-application benchmarks. |
| Search results could leave stale page boxes, scan every repeated match per glyph, or imply a location when Page text and geometry use different reading orders. | Search state is tied to document ID/revision and clears on close, query or case changes, tab switches, and revision changes. A shared literal matcher preserves existing `/u` and `/iu` semantics, maps JS code-unit ranges across Unicode and whitespace glyphs, limits the SearchPanel to its first match, and uses a linear cursor for the 20,000-character geometry cap. Pan mode requests geometry for highlights without rendering selectable text; unsupported, capped, malformed, or unmappable matching pages show a route back to Find results or Page text. Focused tests cover literal regex characters, case, repeats, cross-glyph whitespace, astral Unicode, stale state, pan mode, fallback, and page navigation. A mocked-IPC Vite harness measured 0° and 90° rectangles and preserved selected `A B\né`; it does not verify Windows clipboard or real native IPC. The final source gate passed 80 frontend/release tests and the production build. The standalone Windows debug build passed immediately before the final first-match allocation refinement and will be rebuilt with crop. |
| Crop could target the wrong page, use source rather than displayed bounds, leave a one-point strip unusable, or mutate a session after stale/failing work. | Organize Pages starts with the current reading page selected and crops exactly one selected page. It validates finite, non-negative point insets and a retained width and height of at least one point, previews the resulting displayed dimensions, blocks duplicate submission and close while busy, and keeps the dialog open on an error. Native conversion accepts only the displayed normalized rectangle, rechecks document revision and page state, and treats the full area as a no-op. Native coverage checks all valid fixtures, original and edited rotations, repeated crops, one-point boundaries, protected/stale failures, source preservation, and saved/reopened rendered-pixel preservation. Focused UI tests cover rotation, invalid input, cancellation, retry, duplicate work, current-page selection, page-count clamping, and intentional empty selection. A mocked-IPC browser harness checked the preview and normalized request; it is not native desktop evidence. |
| Default-parallel native tests could contend for the existing four-print-snapshot admission limit. | Test-only print consumers now serialize admission and use RAII cleanup on assertion unwind; a regression verifies capacity is released. Production admission remains four snapshots. The default-parallel native suite passed 52 tests. |
| An unread successful BeginPrint reply could retain an admitted snapshot and exhaust the four-job capacity. | A non-cloneable snapshot lease now queues idempotent cleanup when dropped. The spool thread owns the lease through handoff, source closure, normal completion, and panic; its normal cleanup remains awaited before reporting. The regression failed before the change by rejecting the fifth job, then passed after four unread receivers were dropped. |
| An ordinary Open whose reply closed before delivery could register an unreachable document session. | Open now skips an already closed reply and removes its newly registered document and session when sending the result fails. The regression uses a unique path and a FIFO probe to show no session remains. |
| Successfully sent but unread Open, BeginOpen, Unlock, Combine, or PasswordRequired replies could retain a new session or pending password token. | Private non-cloneable reply leases now clean up only the new document ID or password token until a public service method explicitly accepts its DTO. The five red regressions each retained one item before the fix; afterward, accepted Open, BeginOpen, Unlock, Combine, retry, and cancel results remained usable. An unclaimed Combine still leaves its published PDF intact and reopenable, with source sessions unchanged. This covers worker-to-service receipt only, not acknowledgment by Tauri, WebView, or JavaScript. |
| A FIFO run of live viewer renders could delay Close or EndPrint and retain obsolete render work. | The native request queue looks ahead at most 32 positions only while a viewer Render is at its head. Close and EndPrint can each overtake up to two consecutive renders, while every other request is a strict FIFO barrier and then one render must run. Pure barrier/window/fairness tests and a deterministic actor regression pass. A separate single-fixture manual probe with eight live renders changed Close from 8,985.403 ms with eight renders and 2,931,254 PNG bytes retained to 1.549 ms with zero renders and zero retained bytes; this is not a general performance benchmark. |
| Combining could lose current edits or source history, collide object graphs, merge metadata, publish an invalid/racing output, or falsely succeed after a source changes. | Combine accepts two distinct current document IDs and revisions, checks both before and after the native save dialog, rejects unsupported catalog/page-tree features and unsafe references, renumbers each object graph, and keeps only the first PDF’s Info/XMP metadata. PDFium validates every combined page before tempfile/fsync/noclobber publication. It caps serialized output at 4,096 pages and 256 MiB; those are output guards, not an application memory cap. Native coverage checks all six ordered corpus pairs and every output page, cropped original/edited rotations, pixels/tokens, metadata, stale/closed/duplicate cases, unsupported structures, validation failure, races, source bytes, and source undo/history. UI tests cover order, revisions, cancellation, retry, busy/Escape guards, and activating a clean new tab without changing dirty sources. A mocked-IPC browser harness verified ordered page-count preview, first-metadata notice, and submitted revisions; it is not native save-dialog evidence. |
| Inserting pages could reorder the target, lose its metadata, use stale source plans, or change either source session. | Insert Pages accepts distinct target and donor IDs and current revisions, validates an integer boundary from 0 through the target page count before and after the save dialog, and creates target-prefix + donor + target-suffix output. It retains target Info/XMP metadata even at boundary 0, rejects unsupported structure and existing/racing output paths, validates every output page, and keeps both source histories and dirty state intact. Native tests cover every ordered pair of the three fixtures, all output pages, beginning/middle/end boundaries, cropped original/edited rotations, pixels/tokens, stale/closed/duplicate cases, unclaimed reply cleanup, and source preservation. UI tests cover validation, cancellation/retry, busy/Escape guards, revisions, and activation of a clean five-page copy. A mocked-IPC browser harness checked a 3+2-page boundary preview and its submitted DTO; it is not native save-dialog evidence. |
| Replacing pages could remove the wrong target span, use stale plans, discard target metadata, or let a smaller result bypass structural input guards. | Replace Pages accepts distinct target and donor IDs and current revisions, validates one positive contiguous target range, and creates target-prefix + donor + target-suffix output. It retains target Info/XMP metadata even when the selected span is the whole target, checks the aggregate input page cap before replacement, validates both complete source graphs and every output page, and keeps both source histories and dirty state intact. The source gate passed 109 frontend/release tests, 85 native tests with one separately ignored manual probe, the production frontend build, and a standalone Windows debug build. UI tests cover range and input-cap validation, cancellation/retry, busy/Escape guards, revisions, source preservation, and activation of a clean five-page copy. A mocked-IPC browser harness checked a derived result count and submitted DTO; it is not native save-dialog evidence. A prior interrupted native run had no test-result footer; its cause remains unconfirmed and the captured rerun passed. |

Password tests also cover wrong/correct passwords, canceled or reused request tokens, rendering after unlock, delayed successful results after cancellation, cleared input, and simulated React effect replay. Native encryption fixtures cover RC4-128 V2, AES-128 V4 and AES-256 V5 with protected and empty passwords, rendering every fixture page. Other encryption variants and Windows password-dialog interaction remain unverified.

Updater tests cover interrupted downloads, timeouts, retry, reset progress counters, busy-state restoration, blocked Close/Escape while installing, duplicate-click suppression, and resource cleanup. These use mocked updater calls and do not establish Windows installer recovery.

## Open risks and verification work

- File reads and PDFium's source copy have no total memory limit, and the worker queue remains unbounded. Undo/redo snapshot allocations now share a 32 MiB per-document budget with oldest-history eviction. Close and EndPrint can bypass a bounded head run of viewer renders, but broader rapid-scroll and memory-pressure limits still need measurement.
- Matching page counts do not prove that two parsers repair a damaged page tree in the same order. More damaged-document fixtures are needed.
- Native parser crash isolation, fuzzing, a real-document compatibility corpus and sustained memory-pressure tests remain missing.
- Reply leases stop when a public service method accepts and returns a plain DTO. They do not establish that Tauri, WebView, or JavaScript received that result; post-acceptance transport loss remains unverified.
- Installed-app password/clipboard/restart behavior, including on-page selection with real native geometry, crop interaction, the split folder dialog, and the Combine Files, Insert Pages, and Replace Pages save dialogs, native print output and driver failures, the signed installer upgrade from 0.2.0, interrupted-install recovery and relaunch still require end-to-end verification.
- The [dependency inventory](license-inventory.md) records current license evidence. General notices and five exact MPL source archives are generated, bundled, and hash-checked in a fresh unsigned debug installer extraction. Project licensing, WebView2 distribution terms, signed-release resource verification, and installed notice interaction remain unresolved.

The replacement source gate passed 109 frontend/release tests, 85 native tests with one separately ignored manual probe, the production frontend build, and a standalone Windows debug build. A prior interrupted native run ended after 179 seconds without a test failure or result footer; its cause remains unconfirmed, and the captured rerun passed. The prior source gate passed 102 frontend/release tests, 79 native tests, the production frontend build, and a standalone Windows debug build. The scheduler’s separate manual probe had already passed and was not part of that native test count. The fresh unsigned debug installer extraction hash-checked all five MPL source archives, their manifest, and both notice files. These checks exercise the source and local unsigned artifact; the 0.2.4 draft predates these changes.
