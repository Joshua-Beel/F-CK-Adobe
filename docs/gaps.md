# Gaps versus the supplied feature reference

## Viewer foundation

Embedded-text Find is implemented in the source build: matching pages, highlighted/selectable excerpts, next/previous navigation, case matching, cancellation, a 500-page result cap, and literal highlights over visible supported glyph geometry. Page text can be selected in a separate dialog. Supported embedded text can also be selected directly on rendered pages: geometry covers crop offsets and cardinal glyph rotations, is requested only after visible page images load, and is capped at 20,000 characters. Pan mode keeps search highlights but disables selection. Skewed, mirrored, malformed, over-cap, no-positioned-geometry, or text-order-mismatched matches route explicitly to Page text or Find results; scanned pages normally have no embedded text, and Windows desktop clipboard behavior remains unverified. The bookmark pane supports nested entries and internal page destinations, capped at 1,000 entries; bookmark editing and destination zoom/position remain missing. Reading preferences, recent files and stars persist locally. Opening-password prompts support retries and cancellation; encrypted files remain read-only. Document properties show source metadata, current page dimensions and reported permissions without validating signatures. Native Windows printing is implemented, but printer output and driver cancellation still need verification. Strict app-owned annotations are current source work: sticky notes, area highlights, and supported selected-text highlights can be created, selected, edited, or deleted, and crop-hidden annotations stay editable from the Comments panel. Text highlights map a single browser selection outward to whole native geometry characters and let native rendering derive their quads; they are unavailable for cross-page, stale, unsupported, truncated, or unmapped text, including the pinned engine's astral mapping fixture. Area highlights are dragged rectangles, not text selections; native PDF rendering owns both highlight appearances. Foreign, empty, malformed, signed, encrypted, form, tagged, page-label, and article-thread annotations are explicitly unavailable; bodies do not expose through Page text or Find, and printed pages render native appearances only. Fill forms is current source work for a strict, visible, flat subset of single-line text fields and flat merged checkboxes: text values are printable ASCII, checkboxes retain their validated source appearances, current page plans must be unchanged, and native checks refuse unsupported PDFs without partial output. The source state name of a checkbox is never exposed in the UI. Radio buttons, Fill & Sign, certificates, form preparation, and general form editing remain unavailable. It saves a new copy and leaves the source session unchanged. Organize Pages can split the current edited page order into fixed-size files in a new Windows-selected folder, up to 64 outputs and 256 MiB per output, crop one selected page from point insets in its current displayed bounds, insert every current edited page from a distinct open donor at a selected target boundary into a new copy, or replace one contiguous target range with all donor pages in a new copy. Crop hides content and is not redaction; native desktop crop interaction, the split folder dialog, and the Insert Pages and Replace Pages save dialogs still need verification. Folder search, embedded attachments, layer toggles, tags, signatures, rulers, page labels, alternate page layouts, read-aloud, or drag/drop opening remain unavailable. Files currently stay open in one native worker. Organizer thumbnails are implemented, but viewer-pane thumbnails, progressive low-resolution previews, cancelable priority queues, crash isolation and auto-save recovery remain unimplemented. Native page edits export through lopdf. Documents over 65,536 pages are rejected explicitly.

## Performance and compatibility

No validated 60 fps target, 10,000-page open latency, real 300-dpi scan benchmark, or multi-viewer round trip. The page geometry list is collected at open, rather than a fully lazy page-tree implementation. Frontend page-number lists are not virtualized; rendered page images are. The native cache, undo/redo snapshots and individual print bitmaps have limits; these are not a measured total application RSS cap.

## Remaining tools

Organization now supports rotate/delete/extract, move earlier/later or directly to a numbered position, fixed-size splitting to a new folder, one-page point-inset cropping, insertion at a target boundary, and replacement of one contiguous target range with all current pages from a distinct open donor; each structural copy leaves source sessions unchanged. Strict app-owned sticky notes and highlights follow supported move/delete/extract/split operations, undo/redo, and Save a Copy. Combine Files, Insert Pages, and Replace Pages retain the target/first PDF’s Info/XMP metadata, reject annotated or unsupported page-tree/catalog sources, cap aggregate input at 4,096 pages and serialized output at 256 MiB, and leave source sessions unchanged. Page-label/page-box operations, drag-reordering and extraction into separate files remain unimplemented. Signed or certified documents are rejected for edits; complex page-reference structures are rejected for relevant destructive/structural operations until preservation is implemented. See the tool documentation for exact restrictions.

Creation, text/image editing, format export, OCR, image enhancement, replies, author identity, foreign-annotation interchange, stamps, measurement, comparison, form preparation, Fill & Sign, certificates, password security, sanitization, redaction, PDF standards, optimization, accessibility, print preview, action wizard, custom-tool, index and virtual-printer features remain unimplemented. Selected-text highlighting is limited to supported geometry and is not Acrobat-compatible annotation interchange. Disabled cards are a roadmap, not evidence of implementation.

## Distribution and verification

The installer, signed updater, and release CI are implemented. Published 0.2.0 and the signed but unpublished 0.2.6 draft have separate evidence; the 0.2.6 draft assets, signatures, notices, and five exact MPL source archives were independently checked before the privacy rewrite, but were not rebuilt or re-signed for the rewritten source tag. Installation and the full upgrade/relaunch remain unverified. The [dependency inventory](license-inventory.md) records the remaining project-license and WebView2 distribution review. Automated desktop UI tests and a 200-file real corpus remain outstanding. Synthetic tests and manual UI checks are recorded separately in phase status. The current build must not be used as a redaction, document-signing, PDF/A-conformance, or general form-filling tool.
