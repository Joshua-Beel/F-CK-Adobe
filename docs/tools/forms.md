# Fill existing text fields

Open a PDF and choose **Fill forms** from All tools or the quick toolbar. The dialog lists the text fields that this build can safely preserve. Enter a changed value, then choose **Save filled copy**. Windows asks where to save the output; the open source PDF, its dirty state, and its undo history remain unchanged. The new file opens as a clean tab.

This is a small compatibility slice, not Fill & Sign. It accepts printable ASCII only and checks both a field's character limit and its existing layout before the native operation runs. The native layer checks again before saving. It supports only flat, visible, single-line text fields with one widget, a validated fixed Helvetica style, a fixed supported font size, solid border, and supported gray or RGB colors. A populated field must also have a compatible normal appearance; a blank field can omit one only when its remaining validated style is sufficient. Unsupported fields, actions, signatures, XFA, encryption, unknown appearance/layout content, non-ASCII input, overflow, or an edited page plan make the whole form unavailable or reject the attempted copy. There is no partial fill.

The original document's crop and rotation are preserved. A crop can therefore hide or clip a listed source field: it remains fillable, but this tool does not expand the crop, remove the field, or promise that the saved value is visible on the cropped page or printout.

The form has at most 256 fields. A value is limited to 4 KiB and all field names and values to 1 MiB; the native layer also bounds source parsing, appearance decoding, and serialized output. These are compatibility and output guards, not a memory-use claim.

There is no in-place form editing, form preparation, certificate workflow, handwriting, signature placement, author identity, or general Acrobat form support. Canceling the native save dialog or receiving a native error keeps the dialog's entries so they can be corrected or retried.

The full source gate passed 150 frontend/release tests and 116 native tests with one ignored manual probe, the production frontend build, and the standalone Windows debug build. The native focused form gate passed 9 tests. Native checks cover a ReportLab compatibility fixture with independent pypdf/Poppler inspection, local and inherited crop/rotation, changed-field pixels and values, immutable print snapshot bitmaps, source/reopen preservation, every original page across the three corpus fixtures with an appended independent form page, and receiver/ownership guards. This is evidence for that strict subset, not broad cross-viewer form compatibility. Focused UI tests cover changed-only patches, printable-ASCII and size checks, unsupported forms, cancellation/error draft retention, duplicate-submit and Escape guards, a stale query response, and opening a clean output tab without changing a dirty source tab. A Vite browser harness uses mocked IPC to check the changed patch and cancellation behavior. Native desktop save-dialog interaction and installed-app behavior remain separate work.
