# Fill existing fields

Open a PDF and choose **Fill forms** from All tools or the quick toolbar. The dialog lists the fields that this build can safely preserve. Change a text value, checkbox, or supported radio-group selection, then choose **Save filled copy**. Windows asks where to save the output; the open source PDF, its dirty state, and its undo history remain unchanged. The new file opens as a clean tab.

This is a small compatibility slice, not Fill & Sign. Text values accept printable ASCII only and are checked against both a field's character limit and its existing layout before the native operation runs. The native layer checks again before saving. It supports only flat, visible, single-line text fields with one widget, a validated fixed Helvetica style, a fixed supported font size, solid border, and supported gray or RGB colors. A populated text field must also have a compatible normal appearance; a blank text field can omit one only when its remaining validated style is sufficient. It also supports flat merged square checkbox fields, each with Off and one matching on state across its normal and any rollover or down appearances. Their bounded vector-only artwork cannot use fonts, images, or transforms, and the source styles remain intact rather than being replaced with a uniform check shape. The checkbox's source state name remains internal; the dialog shows only its source field name, page, and checked state.

Supported radio groups are one-level, flat, same-page groups with two through 32 options, Radio and NoToggleToOff flags, and exact matching Off plus one source option state in normal and any rollover or down appearances. Their bounded vector-only artwork cannot use fonts or images and allows only the validated centered translation; the original artwork stays intact. Labels come directly from the source option states, while the dialog keeps opaque widget IDs internal. A source group may begin blank only when its parent V is absent or Off and every child AS is Off; after a selection, this slice offers no clear action. The result preserves the group’s original appearances and default state, then changes only the current parent value and child appearance states. Radio groups spanning pages, shared or missing widgets, ambiguous states, radio-in-unison, signature controls, and other button groups are unavailable.

Unsupported fields, actions, signatures, XFA, encryption, unknown appearance/layout content, non-ASCII input, overflow, or an edited page plan make the whole form unavailable or reject the attempted copy. There is no partial fill.

The original document's crop and rotation are preserved. A crop can therefore hide or clip a listed source field: it remains fillable, but this tool does not expand the crop, remove the field, or promise that the saved value is visible on the cropped page or printout.

The form has at most 256 logical fields and 256 page widgets together. A radio group has two through 32 options. A text value is limited to 4 KiB and all field names, option labels, and values to 1 MiB; the native layer also bounds source parsing, appearance decoding, and serialized output. These are compatibility and output guards, not a memory-use claim.

There is no in-place form editing, form preparation, certificate workflow, handwriting, signature placement, author identity, radio-button editing outside this strict subset, or general Acrobat form support. Canceling the native save dialog or receiving a native error keeps the dialog's entries so they can be corrected or retried.

The mixed-field source gate previously passed 151 frontend/release tests and 123 native tests with one ignored manual probe, the production frontend build, and a standalone Tauri Windows debug/no-bundle build. The radio UI update passed the 152-test frontend suite, the focused native radio gate passed 6 tests, and the full native gate passed 129 tests with one ignored manual probe in 330.47 seconds. The standalone Tauri Windows debug/no-bundle build passed with 1,931 frontend modules in 2.90 seconds and native compilation in 18.76 seconds. Native coverage checks source labels and opaque option IDs, supported blank groups, group-state switching, retained raw appearances/defaults, crop/rotation, reopen and immutable print snapshot bitmaps, corpus source preservation, and receiver/ownership guards. Independent pypdf field-tree/widget/default/appearance inspection and Poppler rendering checked the supplied compatibility case: 267 new-choice dark pixels, none in the old choice, 685 changed pixels, and none outside affected widgets. This remains evidence for a strict subset, not broad cross-viewer form compatibility. Focused UI tests cover changed-only tagged patches, printable-ASCII and size checks, keyboard checkbox input, radio Arrow/Space selection, false/blank/reverted values, unsupported forms, cancellation/error draft retention, duplicate-submit and Escape guards, a stale query response, and opening a clean output tab without changing a dirty source tab. A Vite browser harness uses mocked IPC to check keyboard checkbox and radio patches plus cancellation draft behavior. Native desktop save-dialog interaction and installed-app behavior remain separate work.
