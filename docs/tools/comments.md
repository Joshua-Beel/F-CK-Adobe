# Comments and area highlights

Open a PDF and choose **Comment** from All tools or the quick toolbar. Click a bare part of the page to place one sticky note, type its text, then choose **Save comment**. The PDF renders the note icon; the transparent on-page target opens the editor without drawing a second icon.

Choose **Add area highlight** and drag one rectangle on the current displayed page. It highlights an area, including scans; it does not select or infer text. The PDF renders a fixed translucent yellow appearance. The UI does not draw a second saved fill. A highlight's optional description can be empty; the native layer normalizes whitespace-only descriptions to none and preserves nonblank Unicode text and its surrounding whitespace. The rectangle cannot be resized after creation. Keyboard drawing is not implemented. Escape, a lost pointer, a page move, zoom, or a revision change cancels an unfinished drag.

Use the **Comments** rail button to list every note and area highlight. Select either item to edit or delete it. An annotation fully hidden by the current crop has no on-page target, but remains in the list with an explicit hidden status and can still be edited or deleted. Comment mode enables keyboard-focusable transparent edit targets. Area-highlight placement, Select, and Pan leave those targets inactive, so an existing large highlight does not block an overlapping drag, text selection, or panning. Press **Escape**, choose Select, or press **H** to leave placement mode. While an annotation is saving, closing the editor, tab, or workspace is blocked.

Annotations have no author field in this slice. A note must contain nonblank, NUL-free text. A highlight description is optional. Each body may use at most 8 KiB of UTF-8; a document may have at most 1,000 notes and highlights combined and 1 MiB of text combined. Current page crop and rotation are handled by the native layer, so the UI always sends a normalized position in the displayed page rather than converting PDF coordinates itself.

Supported notes and area highlights follow page rotation, crop, move, delete, extract, and split operations. They participate in undo/redo, Save a Copy, reopening, visible rendering, and immutable print snapshots. Printed pages render their native appearance only; bodies do not enter Page text or Find.

Commenting is unavailable for foreign, empty, malformed, signed, encrypted, form, tagged, page-label, or article-thread annotation structures. This refusal leaves the source unchanged. Combine Files, Insert Pages, and Replace Pages also refuse annotated source documents. Text-range markup, replies, author identity, and foreign-annotation interchange are not implemented.

Verification includes 132 frontend/release tests and 99 native tests with one ignored manual probe; the production frontend and standalone Windows debug builds passed. Native regressions cover cardinal rotations, inherited and offset crops, Unicode, history limits, reopening, note and highlight pixels, immutable print snapshots, supported page operations, and refusal cases. Focused UI tests and a mocked browser harness cover note placement, area dragging, exact image bounds, transparent hit geometry, hidden annotation editing, stale requests, UTF-8 limits, pointer cancellation, mode behavior, and busy/Escape handling. Desktop save-dialog and saved-output interaction, actual printer output, and installed-app checks remain separate evidence.
